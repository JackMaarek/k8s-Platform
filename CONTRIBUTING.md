# Contributing to k8s-platform

## Branch model

```
main      ←  source of truth — placeholders only, never env values
dev       ←  platform-bot derivative of main (auto-managed, never edited directly)
feat/*    ←  new features, branched from main
fix/*     ←  bug fixes, branched from main
chore/*   ←  maintenance (deps, docs, refactors), branched from main
```

**Hard rules:**
- Never commit directly to `main` or `dev`
- Never put env-specific values (`eu-west-3`, `env: dev`, account IDs) on `main`
- `dev` is always regenerated by platform-bot after a merge to `main` — do not edit it manually
- One PR per logical change — keep diffs small and reviewable

---

## Starting a feature

```bash
git checkout main
git pull origin main
git checkout -b feat/my-feature   # or fix/ or chore/
```

Work, commit using Conventional Commits (see below), then open a PR toward `main`.

---

## Conventional Commits

All commits must follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <short description>

[optional body]
[optional footer]
```

### Types

| Type | When to use |
|------|-------------|
| `feat` | New feature or capability |
| `fix` | Bug fix |
| `chore` | Maintenance — deps, docs, refactors, config |
| `refactor` | Code restructure without behavior change |
| `ci` | CI/CD pipeline changes |
| `test` | Adding or fixing tests |

### Scopes

| Scope | Target |
|-------|--------|
| `terraform` | Any file under `terraform/` |
| `argocd` | ApplicationSets, AppProjects under `argocd/` |
| `istio` | Istio configuration |
| `monitoring` | Prometheus, Grafana, Loki, Promtail |
| `kyverno` | Kyverno policies |
| `eso` | External Secrets Operator |
| `platform-bot` | The CLI tool |
| `k8s` | Raw Kubernetes manifests |
| `docs` | Documentation only |

### Examples

```
feat(monitoring): add per-datasource ConfigMaps with fixed uids
fix(istio): disable sidecar injection on ingressgateway pod
chore(terraform): bump EKS version to 1.33
refactor(argocd): split prometheus-values into prometheus + grafana
```

## Placeholder convention

`main` uses `__SNAKE_CASE__` placeholders wherever a value differs between environments.
Platform-bot replaces them at `init` time when generating a branch for a specific env.

| Placeholder | Replaced with |
|-------------|---------------|
| `__ENV__` | `dev` / `staging` / `prod` |
| `__TARGET_REVISION__` | git branch name for the env |
| `__AWS_REGION__` | `eu-west-3` |
| `__AWS_ACCOUNT_ID__` | AWS account ID |
| `__ESO_IRSA_ROLE_ARN__` | IRSA role ARN for ESO |
| `__CLUSTER_NAME__` | EKS cluster name |
| `__REPO_URL__` | GitHub repo URL |

**Never replace a placeholder manually** on `main` — if you need to test a value, do it on a feature branch and strip it before merging.

## File size and SRP

- **200 lines max per file** — split if exceeded
- **One responsibility per file** — a values file owns one component, a manifest owns one resource type
- **Comments on complex logic** — explain *why*, not *what*
- No shell scripts in `k8s-platform` — this repo is purely declarative

---

## PR checklist

Before opening a PR, verify:

- [ ] Branch is based on latest `main`
- [ ] No env-specific values on files that go to `main` (`grep -r "env: dev\|eu-west-3\|k8s-platform-dev" argocd/ kubernetes/helm/`)
- [ ] No placeholder left unreplaced (`grep -r "__ENV__\|__CLUSTER_NAME__" kubernetes/manifests/`)
- [ ] Commit messages follow Conventional Commits
- [ ] No file exceeds 200 lines
- [ ] No secrets or credentials committed
- [ ] `argocd/` changes include a wave annotation comment if ordering matters

---

## After merge to main

Platform-bot handles `dev` automatically:

```bash
# Run by platform-bot — do not run manually unless debugging
git checkout dev
git rebase main
platform-bot init --env dev
git push origin dev --force-with-lease
```

If you need to validate your change on the cluster before merging:

```bash
# Apply only your feature branch manifests to the local cluster
kubectl apply -f <path> --dry-run=server
```
